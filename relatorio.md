# Introdução

Neste relatório será apresentada uma breve demonstração do funcionamento do protótipo desenvolvido no Figma, que explica as suas principais funcionalidades e a forma como 
este responde às necessidades dos perfis fornecidos. Além disso, será incluída uma análise que comprova como o projeto segue as oito regras de ouro de Shneiderman, garantindo
uma interface intuitiva, coerente e centrada no utilizador.

# Funcionalidades principais

Como primeira frame do nosso protótipo, é apresentada secção de login do utilizador, que, após alguns cliques, revela as credenciais de José Silva.
Numa instância seguinte, é disponibilizada a opção de selecionar um país e uma cidade, e neste caso foi escolhida Lisboa como caso principal.
    Após aplicar essa escolha, o utilizador tem acesso a uma variedade de informações sobre cidade selecionada, desde estatísticas sobre os alojamentos até gráficos    
temporais, um mapa interativo que mostra a densidade de AL e a opção de exportar dados no formato desejado.
Nesta página, é também possível aplicar filtros mais avançados, ao clicar no botão “Filtros”, onde definimos um exemplo de filtragem de “Casa/apartamento completo”, data
inicial e final, preço por noite num intervalo, duração de estadia exata de 6 noites, e uma pontuação de uma até cinco estrelas.
    Com estas opções disponíveis conseguimos abranger todas as necessidades do Perfil 1, e facilitar a sua recolha e análise de dados.
    Ao visualizar os resultados dos filtros avançados, o utilizador depara-se com quadros adicionais e alertas sobre dados anómalos para determinadas zonas. Está presente
também um quadro de casos emblemáticos, que destaca áreas com estatísticas significativamente diferentes das restantes.
    Esta coleção de funcionalidades, juntamente com o texto junto do mapa, que indica a última atualização dos dados apresentados, forma o ambiente ideal
para o Perfil 2 de Maria Santos, permitindo-lhe realizar o seu trabalho com uma visualização clara e direcionada para as suas visões políticas.
    De modo a implementar as ferramentas necessárias para o Perfil 3, foram adicionadas as opções de criação de gráficos e comparação de cidades. Para visualizar um exemplo
da criação de um gráfico personalizado, devem ser escolhidas as opções, “Linha” para tipo de gráfico, 1 como número de variáveis, número total de listagens como variável Y, e
tempo como variável X. Após gerar o gŕafico, é apresentada a opção de fazer download do gráfico como imagem, ou partilhá-lo numa rede social, neste caso, o Instagram.
    Por fim, de modo a testar a comparação entre cidades, podemos voltar atrás para a frame com os dados de Lisboa e selecionar o botão “Comparar”. No país e cidade será
selecionado o Porto, e os parâmetros a serem analisados são o número médio de listagens por host e o número total de listagens.
    Após percorrer todos estes cenários as principais funcionalidades deste projeto terão sido observadas e testadas, permitindo avaliar a interatividade do protótipo e gerar
conhecimento relevante para a verificação das heurísticas de Shneiderman.

# Avaliação de usabilidade

Procuramos sempre dar mensagens claras de erro, escolhemos a cor vermelha para que não fosse possível ignorar e com um texto claro, por exemplo: Escolha primeiro um país,
quando o utilizador tenta escolher uma cidade antes de escolher o país. 
    Usámos também texto simples que, alguém, tanto dentro como fora da área entenda, nos botões e nos quadros onde mostrámos os dados.
    Evitamos ao máximo que o utilizador cometa erros, gerando casos de erro caso ele tente introduzir dados fora de ordem. Além disso, para que o utilizador não tenha de
memorizar informação enquanto usa o site, mostrámos sempre informações como os países selecionados na mesma tela em que os dados são analisados e os filtros a apenas um
clique no botão filtros, na parte de cima da frame.
    Para manter também uma interação clara, sempre que o utilizador necessita de uma resposta por parte do sistema, nas transferências ou partilhas é apresentada uma mensagem
a verde a indicar que a ação foi concluída com sucesso. 
    Usamos apenas atalho específico, “seleciona tudo”, na seleção de dados a comparar para evitar muitos cliques caso o utilizador quisesse comparar tudo. Não usamos mais pois
pensámos que tudo já está bastante acessível e claro para utilização. Mantemos sempre a interface centrada nos dados a analisar e com funcionalidades referentes a outras
ações nos cantos para manter uma imagem mais limpa.
    Essas funcionalidades foram aplicadas como forma de botões que podem levar a novas frames, como a comparação de dados e criação de gráficos para evitar poluição visual e
confusão.
